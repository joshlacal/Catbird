# Scene-owned drafts, account transfer and sharing handoff

This follow-up implements the social lane's portion of LITE-017, the repair that gives each app window its own navigation and editor ownership. It prevents one window's autosave, dismissal, account switch or shared message from taking over another window's draft. Lite and the focused Full counterpart preserve the original saved-draft synchronization repairs; Full also retains Circle publishing and encrypted-chat behavior. The source is intended for integration with the separately owned scene shell and lifecycle hooks, followed by the combined build and two-window runtime checks. ## Implemented behavior and ownership

- The account-owned saved library stays in `ComposerDraftManager`; active editing moves into `SceneComposerEditingSession` with immutable account/scene claims, content revisions and a distinct visible-editor lease. Save and delete compare the last-observed saved-row body. A concurrent remote edit remains intact while the local version becomes visible recovery content. A weak live provider saves final typing synchronously before ownership changes, even when autosave is off or teardown is cancelled. See [draft/session report](scene-drafts.md).
- Composer entry points require the scene session; only an explicit editing claim resumes its existing body. Autosave, saved selection, submission completion, minimized resume and legacy recovery use the exact claim and presentation lease. Serialization caching preserves unchanged image identities, and submission recovery uses the captured editor body rather than temporary upload fields. Full keeps Circle destination and reply-lock semantics. See [composer call sites](scene-composer.md).
- Account transfers carry immutable source-scene, target-account and request identity. The destination can claim the body exactly once only after verified switch completion. Suspension is reversible; source retirement is awaited before target services start. Explicit rollback must restore the exact source account, and cancelled callers cannot invalidate a switch that already committed. See [account-switch report](scene-account-switch.md).
- Post shares and message intents bind content to account, scene and request before navigation, then publish only after deferred revalidation. Consumption is synchronous and exact-token; consumed text remains available for explicit recovery without automatic replay. Full uses a separate protected scoped table and preserves the legacy MLS payload/table/API. See [sharing report](scene-sharing.md).

Shared media files are deliberately retained until reference-aware collection exists: another scene, source saved row or transferred editor may still use them. This can retain unused local files. No post, message, appeal, reaction or authenticated account-data mutation was performed.

## Integration contracts

The integration owner supplies stable `SceneNavigationContext` identity above account-specific view identity, its account-scoped editing session, scene-bound composer requests, and queue invalidation. `PostComposerViewUIKit` requires `editingSession`, accepts an optional exact `editingClaim`, and retains Full's destination argument. No dynamic global current-scene fallback is valid.

The shared routing coordinator must select the destination before its synchronous `beforeDelivery` binding callback and retain/expire the exact request correctly. Full's direct-message presenter is `presentMLSDirectComposeDraft`; the consumer must revalidate account/scene/conversation/token after durable peek, claim synchronously before insertion, and acknowledge afterward without making consumed recovery rows eligible for replay. The original `ConversationView` does not consume MLS intent drafts.

The shell supplies throwing `suspendForAccountSwitch`, `resumeAfterInterruptedAccountSwitch` and `retireAfterAccountSwitch` hooks. Full AuthManager must honor `deferMLSStorageChanges: true` for both target and rollback calls. Retirement includes awaited ordered teardown, the final database drain and release of the exact suspension gate. Failure after destructive retirement enters Restart Required; it must never restart destroyed source services. Rollback calls `resumeAfterInterruptedAccountSwitch(using: restoredClient)` and never calls updateClient: the client and suspended service objects must remain the original instances. Restricted source lifecycles remain restricted until verified reactivation, and logout retains the admitted source identity through cleanup. The retained-client hooks are sealed at Lite `13a36f79e72493da4a642832cd09e74f9a959b03` / Full `5c3ccf6e850feb5d56fd2252e029441e3388e84c`.
