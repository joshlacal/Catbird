## 2026-10-02 · Feed loading · Prepare cache payloads away from the UI and retain unchanged rows
Chose: serialize Sendable post/thread-slice payloads on a concurrent executor, construct SwiftData models on their existing UI actor, prime decoded caches, and compare value snapshots before clearing presentation caches or reconfiguring collection rows (provisional). Because: the synchronous cache helper executes on its caller despite its name, newly decoded posts are immediately decoded again, and every collection publication reconfigures surviving rows including unchanged Trending content. Rejected: treating the already integrated Petrel decoder benchmark as proof of scrolling improvement, moving SwiftData model instances between executors, or freezing Trending to a fixed height.
Reversible until: merge of the feed-performance candidate. Override by: replace the preparation/reconfiguration seam and retain passing cancellation, ordering, thread-slice, payload replacement, update serialization and viewport tests. Governing plan: [parallel feedback execution](/Users/joshlacalamito/Developer/Catbird+Petrel/docs/execution-plans/2026-10-02-live-feedback-parallel-execution.md). Aggregate signposts record operation counts and geometry only. Controlled simulator results must be reported separately from authenticated phone smoothness; the integration owner retains phone and quiet-machine qualification.


## 2026-10-02 · Window isolation · Keep feed viewports in the scene and aggregate feed lifecycle
Chose: a scene-owned FeedViewportStore keyed by account and feed, with explicit controller injection and atomic manager/viewport rebinding; keep FeedStateStore data managers shared. Scroll commands use controller-owner tokens so outgoing controller teardown cannot unregister its replacement. Aggregate scene activity by a unique context-lifetime UUID, retain work while any scene is active or foreground-inactive, and guard asynchronous background effects with a lifecycle revision (provisional). Because: shared scroll anchors allow one window to overwrite another's reading position, while anonymous scene-phase broadcasts can cancel shared loads used by an active window. Rejected: duplicating feed managers and network work per window or using global fallback viewport state.
Reversible until: merge of the window-isolation integration. Override by: replace the scene UI-state and lifecycle seam while retaining two-window anchor/command, stale-owner cleanup, account-context replacement, and stale-background-effect regressions. Governing plan: [parallel feedback execution](/Users/joshlacalamito/Developer/Catbird+Petrel/docs/execution-plans/2026-10-02-live-feedback-parallel-execution.md). Integration owns SceneNavigationContext, root registration/disconnection/account replacement, and bridge/wrapper injection; this source commit requires that coordinated wiring before app qualification. No persisted feed-data or scroll-position schema changes are introduced.
