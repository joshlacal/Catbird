# Scene-owned composer editing

This follow-up separates a window's active post editor from the account's shared saved-draft library. Previously, selecting a saved draft in one window changed the identity used by autosave, discard and submission in another window. Each scene now owns an immutable account/scene session with a rotating claim and content revision; library writes validate an exclusive saved-row claim synchronously. Integration owns navigation, presentation and account-switch wiring, followed by the combined application build and two-window runtime verification.

Governing scope: [parallel execution plan](/Users/joshlacalamito/Developer/Catbird+Petrel/docs/execution-plans/2026-10-02-live-feedback-parallel-execution.md) and [composer scene continuity audit](/Users/joshlacalamito/Developer/.workspaces/catbird-live-feedback-20261002/social/evidence/composer-scene-audit.md). ## Provisional choices for integration's decision log

- Chose synchronous main-actor session mutations and final storage writes. Stash, completion and transfer compare the full captured claim, revision, body and saved-row identity before any mutation; stale stash throws without persisting. This closes a guard-to-write suspension gap without changing DraftPersistence or its wire/model format. Reversible before integration merge by adjusting the session API and all dependent callers together.
- Chose application-wide main-actor saved-row claims keyed by account and row identity, enforced by each shared manager. A second scene receives a specific ownership error; it cannot silently take over another scene's row. Library deletion also refuses an actively claimed row. Reversible before merge by implementing an explicit focus-or-copy action rather than changing silent ownership semantics.
- Chose account-and-scene-scoped outer recovery envelopes, keeping PostComposerDraft bytes and the SwiftData schema unchanged. A fresh runtime claim is minted on recovery. The envelope records the last observed saved-row body; a changed, missing or already-claimed row restores as a detached editor, preserving both versions. Replacement, transfer and invalidation retain new content as a visible local recovery-library row, avoiding inaccessible window-specific archives. An already identical durable row is reused. Invalidation also keeps the scoped envelope and points it at the recovery row when one was created. Reversible before merge by migrating envelope keys while retaining prior bytes.
- Chose explicit legacy recovery only. The old unowned composerMinimizedDraft key is never read, attached or removed during manager/session initialization or account observation. The recovery action saves an account-owned library row before removing only the exact bytes it read. Malformed bytes and failed saves stay untouched. Reversible before merge through explicit recovery UI, never automatic account attribution.
- Chose conservative media retention during all editor teardown. A transferred body can refer to media retained by the source account's row or recovery envelope, and there is no complete reference index yet. Discard, submission, transfer and invalidation do not unlink media; future reference-aware garbage collection can reclaim unreachable files. This may retain unused local media but prevents cross-scene/account data loss. Reversible before merge only with verified reference-aware cleanup.

- Chose a separate presentation lease (a UUID per view model) while retaining the durable scene/saved-row claim during minimize and resume. Attaching a new model replaces only this lease; delayed work and release from the dismissed model cannot affect the new model. install, finish and invalidate clear it. Reversible before integration merge by replacing all caller guards together with an equivalent presentation-generation mechanism.
- Chose expected saved-body baseline checks at every existing-row save and deletion boundary, including autosave, discard and successful submission. A claim alone cannot exclude remote reconciliation. When the stored body changed, preserve it exactly and move the current editor to a visible local recovery row before reporting failure. Revision advances to invalidate older snapshots, and the original saved-row claim is released only when recovery uses another row. Reversible before merge only with equivalent conflict preservation for both update and delete.

- Chose an exact claim-and-presentation-bound live draft provider to capture typing when edit autosave is disabled. The view model registers a weak closure; session teardown, replacement and transfer flush it synchronously after checking both owners before and after invocation. Teardown flushing ignores task cancellation and global authentication changes because the source account's local recovery still belongs to its immutable owner. Old unregister operations cannot remove a replacement provider. Reversible before merge only with an equivalent synchronous live-content handoff.

## API

SceneComposerEditingSession has immutable sceneID/accountDID and read-only currentDraft, savedDraftID, activeClaim, isMinimized and lastIssue. beginNew(draft: PostComposerDraft? = nil) and restoreSaved(_:) return a claim or throw; the nil/default body starts an empty composer. update(_:claim:), minimize(claim:) and resume(claim:) return false for stale/cancelled work. snapshot() returns an immutable ComposerEditingSnapshot. stash(_:) returns the durable row UUID or throws. discard(claim:), completeSubmission(_:) and detachForTransfer(_:) return false on ownership, revision or storage failure. invalidate() preserves recovery and rejects all future editing callbacks. recoverLegacyDraft() is explicit and durable before legacy-byte removal. claimEditor(_:claim:), ownsEditor(_:claim:) and releaseEditor(_:claim:) return Bool and distinguish the latest visible view model from an older model retaining the same durable draft claim. registerLiveDraftProvider(editorID:claim:provider:) and unregisterLiveDraftProvider(editorID:claim:) return Bool; the closure returns the current PostComposerDraft synchronously, captures its view model weakly, and must not depend on current global authentication or cancellation-sensitive editor checks.

The existing saved-selection regression now uses the scene session API. No application build, simulator run or account mutation was performed by this lane. Integration must execute the combined tests and verify the real two-window and account-switch cancel/success flows before declaring runtime completion.

Independent narrow source review identified and then verified fixes for three recovery failures: stale envelopes overwriting newer saved rows, inaccessible archived content, and failed saved-row recovery being overwritten by a fresh composer. Both repairs are implemented; this is source evidence rather than executed application qualification.
