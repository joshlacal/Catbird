# Scene-owned account-switch handoff

This change makes a composer account transfer belong to one originating window, one destination account and one single-use handoff token. The account picker now completes the composer flow only after an explicit successful switch; cancellation, same-account selection, overlap and failure do not invoke that completion. Lite and Full source changes and focused regression tests are ready for the integration build. Full retains its encrypted-storage shutdown contract, with destructive retirement deferred until the destination authentication and account status are verified.

## Implemented contracts

- `PendingComposerReopen` contains immutable `id: UUID`, `sourceSceneID: UUID`, destination `accountDID: String`, and `draft: PostComposerDraft`. Its ID is fresh per accepted transfer, independent of the source editing claim token. The source saved-row ID is never transferred.
- `@discardableResult AppStateManager.switchAccount(to:composerTransfer:) async -> AccountSwitchOutcome` accepts an optional `ComposerEditingSnapshot`. Existing no-draft calls remain valid. Outcomes are `switched(accountDID:reopenID:)`, `unchanged`, `busy`, `failed(String)` and `cancelled`.
- `pendingComposerReopenRevision` is observable through the main-actor queue. `pendingComposerReopen(sourceSceneID:accountDID:)` and `claimComposerReopen(id:sourceSceneID:accountDID:)` are synchronous. Both require the exact ready authenticated lifecycle and actual authentication DID; claiming also matches the exact scene and ID before removing the item once.
- `AccountSwitcherView(showsDismissButton:composerTransfer:onSwitchCompleted:)` invokes its optional main-actor completion only for a verified `switched` result. No disappearance callback or fixed readiness delay is used. Interactive dismissal and the cancel control are disabled while an accepted account switch is settling. Ordinary cancellation and selecting the active row retain the editor.

## Switch and recovery behavior

Admission rejects overlap before changing lifecycle or queue state. The source snapshot account must match the active authenticated account. Accepted newer switches revoke older unclaimed handoffs, including a later no-draft switch. A completed handoff is not published until the destination's actual authentication DID and lifecycle agree. External lifecycle/account changes also invalidate stale handoffs.

Authentication events are coalesced while an explicit switch or logout owns the transition; stale queued auth events are ignored. Busy authenticated transitions throw instead of pretending to complete. Target authentication is checked immediately after switching and after the account-status request, and again after source retirement. The status request uses the client directly before constructing any target AppState; a restricted destination never replaces an existing source lifecycle. Target construction/configuration happens only after the source retirement hook returns, so constructors cannot start target work while source services are still live. New target states that fail before publication are removed from the cache so retries do not skip their initialization.

Before changing the shared authentication client, the manager awaits the source's reversible suspension hook. A failure before source retirement switches authentication back if necessary, retains the same source `AppState`, and awaits its resume hook only for the verified original DID. Recovery runs independently of cancellation of the requesting task. Logout revokes the handoff, blocks new admission, waits for every started authentication/recovery operation to settle, then clears credentials. A stale recovery cannot restore lifecycle after logout.

Full's authentication call opts into `deferMLSStorageChanges: true` for both target authentication and rollback. This requires the AuthManager adapter to defer source MLS shutdown, Circle invalidation/cache purge, target database prewarm and MLS active-DID publication. After target authentication/status succeeds, AppStateManager performs coordinated source Rust/Swift teardown, requires the final database drain, invalidates and purges source Circle caches, and prewarms the target database before publishing/initializing the target. Full MLS switch coordination, serialization, data-service wiring and active-user publication remain in place.

Full tracks the destructive retirement phase separately from reversible authentication. A drain failure, mismatch or cancellation after retirement begins cannot resume the retired source services: it reports **Restart Required**, preserves composer/session storage, and blocks further switching until restart. This deliberately makes no claim that old MLS service objects can be reconstructed safely after partial closure.

No pending draft is copied into an account manager's `currentDraft`, and neither the source saved row nor legacy minimized bytes are modified by this code. Source snapshot detachment and destination session creation remain the composer/scene owners' responsibilities; the destination begins without a saved-row ID.

## External integration contracts

The shell owner supplies `AppState.suspendForAccountSwitch() async throws`, `resumeAfterInterruptedAccountSwitch(using expectedClient: ATProtoClient? = nil) async throws`, and `retireAfterAccountSwitch() async throws`. The pause/resume hooks must preserve original service objects on reversible failure and fence/cancel/await their old network callbacks. Suspension failure prevents authentication from starting. Resume failure enters Restart Required rather than exposing partially resumed services. The retirement hook must await the existing ordered source teardown and final drain, including Full's DEBUG database-drain override contract; the manager does not launch raw cleanup as its retirement barrier. Successful retirement must also release the exact owned suspension admission gate without restarting source work. Calling destructive `cleanup()` as the reversible pause is forbidden: Full cleanup clears MLS and Circle services.

The Full AuthManager owner supplies `switchToAccount(did: String, deferMLSStorageChanges: Bool = false) async throws`; all other direct callers retain their original default behavior. Project membership, app lifecycle scene routing, composer callers, draft sessions and builds remain with their assigned integration owners.

## Verification and remaining gates

`swift -frontend -parse` passed for the owned Lite and Full source/test files. No Xcode build, executable test run, device operation or network account action was performed in this lane. The AppState/AuthManager integration hooks were still being supplied when this report was written, so parsing is not a compilation or runtime claim.

`ComposerAccountSwitchQueueTests` directly exercises the production queue and operation barrier in nine focused tests: exact scene/account/token single consumption; overlap retaining the first transfer; external-transition/same-account/stale-source rejection; failed/mismatched authentication without publication; stale/cancelled completion isolation; cancellation before retirement preventing commit; cancellation after retirement preserving verified success; no-draft/account-round-trip invalidation; and logout waiting for authentication plus rollback. It uses no live accounts or networking. Full's existing `SettingsRuntimeWiringTests.retentionStopsForSwitchAndLogout` now checks that status validation precedes source retirement and target construction, awaited retirement precedes target publication, and logout still invokes retention-stopping teardown before credential logout.

The integration gate is a compiled run of those tests plus the real two-window flow: open separate saved rows, switch from one composer, cancel or fail a switch and verify its editor remains intact; successfully switch and verify only the originating window reopens with the copied body; save there and verify it creates a target-owned row while the source row/media remain intact. Exercise logout during a controlled switch/rollback and verify no late authentication or reopen wins. Capture screenshots and runtime logs for these outcomes. Full additionally needs a controlled drain-failure check proving the restart-required boundary and no dead-service resume.

Independent final review corrections: Lite now calls the throwing suspend hook before changing authentication. An explicit rollback that cannot recover the original source DID enters Restart Required and never constructs a fallback target. Full generation advances only after successful awaited source retirement; entering the launching lifecycle preserves source MLS coordination identity until commit. Caller cancellation is forwarded to the exact queued attempt even through Full's unstructured serializer. A synchronous retirement-admission gate distinguishes cancellation before commit (cancel and recover) from cancellation after commit (complete the verified successful switch); admitted retirement settles independently of the requesting task. The Full retention assertion accepts the parameterized restart helper and checks generation ordering. No serializer source changes were needed.

Restricted-source rollback repair: recovery now recognizes any previous lifecycle carrying an AppState, including deactivated and taken-down accounts. Exact source authentication restores that same previous lifecycle rather than promoting it to authenticated. The normal-service resume hook runs only for a previously authenticated source; restricted sources keep their interstitial. Failed exact source restoration remains fail-closed. A focused source regression covers this guard and resume ordering in both variants.

Logout-source repair: each accepted switch retains the exact source AppState and attempt ID before entering launching. Logout captures that state before revoking the queue, waits for the authentication/recovery operation barrier, awaits the idempotent retirement hook for the interrupted source, removes its cache/access-order entries, and only then clears credentials. Source retirement failure leaves the restart fence set. Ordinary logout retains its existing cleanup path. Matching-attempt defer prevents a stale completion from releasing another source capture.

Retained-service rollback repair: rollback no longer invokes `previousState.updateClient`, which would discard Full's retained MLS graph while suspended. Exact restored client identity must match the original AppState client before lifecycle restoration; the authenticated source then calls `resumeAfterInterruptedAccountSwitch(using: client)`. A restricted source restores its original interstitial only after the same identity check, and does not resume normal services. A replacement client fails closed instead of rebuilding the graph.

Final source verification: both managers and the identical queue tests parse successfully after these repairs. The suite now has nine queue/barrier tests and two source-wiring regressions. The new regressions cover source capture before launching, logout retirement/eviction after operation settlement and before credential clearing, exact client identity before restoration, and absence of `updateClient` in rollback. They assert retained-service wiring, not a live service graph or real-account outcome; those remain integration runtime gates. Both variants' owned source is frozen for the combined build.

Verified-reactivation repair: a previously restricted retained source stays suspended during rollback. Reactivation now admits only the exact current source/client with no competing switch, joins the operation barrier for logout, requires confirmed active account status, awaits `resumeAfterInterruptedAccountSwitch(using: client)`, rechecks source/auth/client ownership, and only then publishes authenticated lifecycle and initializes. The restricted-source regression also covers confirmed-active → resume → publication → initialization ordering. No live reactivation request was made.
