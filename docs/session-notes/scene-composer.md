# Scene-owned composer call-site handoff

This work moves the composer editor away from one account-wide mutable draft slot to the editing session owned by its originating window. It implements the composer portion of LITE-017, the scene ownership repair, using the manager/session and account-switch contracts supplied by the parallel owners. The editor, its saved-draft selection, autosave, submission cleanup, minimized accessory, and transfer callback now use explicit scene claims plus a per-presentation lease. The focused Full counterpart is also ported, preserving Circle publishing, audience selection, reply locks and test fixture paths. Source parsing passes, but these edits are not yet qualified by a combined app build or running-device evidence; integration owns those gates and the combined Full app validation.

## Exact contract

All three `PostComposerViewUIKit` initializers preserve their existing leading arguments and require `editingSession: SceneComposerEditingSession` after `appState`. They accept optional `editingClaim: ComposerDraftClaim? = nil` after it. Each view model has a distinct presentation UUID registered through session `claimEditor`; `ownsEditor` verifies it at every mutation boundary. Resuming keeps the durable saved-row claim but atomically replaces presentation authority, so the dismissed model cannot write, discard, transfer or complete the resumed editor. A nil claim always starts a fresh editor from the explicitly supplied text/reply/quote/draft/captured-media request. An explicit claim resumes only an exact session/account/scene token match and restores that session snapshot. The view never guesses a working draft from a shared manager or unspecified presentation arguments.

The view model accepts an optional session solely so pure, non-presented model tests remain usable. Every production UIKit composer initializer requires the real scene session. Without a session, editing storage operations do nothing; there is no global fallback.

`createPost()` and `createThread()` are now `@discardableResult async throws -> Bool`. True means the captured editor was safely completed; false means publication returned but cleanup was rejected because ownership, saved-row state, revision, or live content changed. The UI keeps that newer editor open, resumes its autosave, and does not clear it. Existing callers that intentionally ignore the result remain source-compatible.

## Converted paths

- `PostComposerViewModel`: explicit start/resume/restore, snapshot capture, claim-checked autosave/discard, in-memory submission content comparison, and exact completion. The parent-requested `isolated deinit` correction is included without copying the frozen model.
- `PostComposerCore`: all four account-manager clear operations removed; post and thread paths capture ownership before suspension and complete only the captured session. Duplicate submissions are rejected before touching the editor snapshot. Thread video preparation now restores the original editor video with `defer`; image preparation also restores the original media on failure.
- UIKit root/actions/sheets/thread/account-switch files: required session propagation; canceled sleeping autosave exits without writing; disappearance saves synchronously under its claim; stash/discard use exact session mutations; successful switch is the only composer-dismiss callback.
- Saved-draft selection synchronously flushes current typing before archiving the editor, then replaces the model and its presentation lease. Late asynchronous media/hydration callbacks retain the old model and no longer have authority. Selecting the already open saved row leaves the existing model and claim intact.
- Account picker input is captured before presentation. `AccountSwitcherView(composerTransfer:onSwitchCompleted:)` receives that immutable snapshot, and a verified switched result with a target account and reopen ID detaches the exact source snapshot. Cancel, same-account selection, busy and failure do not invoke that path. Detach never calls destructive manager clear.
- `TabViewBottomAccessoryWrapper`: reads/minimizes/resumes/discards only its context's session; exact active claim is passed into resume presentation. It provides an explicit confirmed Recover Earlier Draft action explaining that the old draft has no verified account and will be recovered for the current account.
- `ThreadComposePrompt`: routes its default reply action through its originating `SceneNavigationContext`.

The only remaining composer-manager reads in this owned surface are the account's saved-draft library and count. No owned clear/discard/transfer path unlinks media files.

## Existing media serialization caveat

`CodableMediaItem` writes raw image data to a fresh file name whenever a persisted body is built. Rebuilding a supposedly unchanged submission body would therefore change its revision. Per integration direction, media encoding and file ownership were not changed. Submission captures once, suspends autosave while active, disables editor interaction, and compares an in-memory content snapshot before completion without reserializing images. The comparison includes actual media bytes, attributes, captions and thread media, not only media IDs. A change conservatively retains the editor.

## Final live-provider preservation seam

Each model now weakly registers a synchronous live draft provider with its exact draft claim and presentation UUID. Scene invalidation, editor replacement and source transfer can flush the body before SwiftUI calls `onDisappear`; unsaved typing in another window is therefore available to the source-owned session. The provider checks its captured local claim only and does not consult the active global account or task cancellation. The session validates the exact lease around invocation. Resume takes the lease first, allowing the outgoing provider to flush, then restores the refreshed snapshot.

The model caches the serialized body alongside the in-memory content comparison. Identical content reuses the same draft and media references instead of creating new image files or incrementing the session revision. While submission is active, the provider returns the preflight editor body captured before submission begins, preventing temporary per-entry upload fields from being persisted during unrelated account teardown. Full's existing Circle destination freeze remains in place.

The provider captures the model weakly, and `isolated deinit` unregisters/releases only its exact claim and presentation UUID. A stale model cannot remove the replacement model's provider. Seven additional focused cases cover two-window invalidation before disappearance, resume before autosave, weak lifetime plus stale unregister/deinit, unchanged photo revision, stale transfer with newer source typing, frozen submission recovery, and canceled source teardown after a distinct target-account editor is created. Authentication itself is not mutated by these fixtures; combined shell/lifecycle qualification remains an integration gate. Both variants pass frontend parsing with the final provider/session APIs; these newly added tests have not been executed by this worker.
